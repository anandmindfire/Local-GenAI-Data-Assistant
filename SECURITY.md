# Security Policy

## Overview
The **Local GenAI Data Assistant** is designed with a strict **privacy-first, local-only architecture**. All natural language processing, vector retrieval, and database queries are executed locally on the host machine or within isolated Docker containers without transmitting enterprise data to third-party cloud APIs.

## Security Architecture & Controls

1. **SQL Injection Defense**:
   - Natural Language to SQL (NL2SQL) queries are generated by local LLMs and strictly validated via AST parsing using `sqlglot`.
   - Read-only enforcement: `INSERT`, `UPDATE`, `DELETE`, `DROP`, `ALTER`, `TRUNCATE`, and multi-statement queries are categorically blocked before execution.
   - Database queries run using a dedicated PostgreSQL read-only user (`genai_readonly`) with table-level `SELECT` grants only.
   - All executions are bounded by hard timeouts (`statement_timeout=5000ms`) and result limits (`LIMIT 100`).

2. **Path Traversal & Ingestion Defense**:
   - Ingested files are sanitized via `sanitize_filename` to prevent path traversal (`../`) attacks.
   - Only approved MIME types (`application/pdf`, `application/vnd.openxmlformats-officedocument.wordprocessingml.document`, `text/plain`, `text/markdown`) and extensions (`.pdf`, `.docx`, `.txt`, `.md`) are permitted.
   - File uploads are capped at a strict maximum size (25 MB) with chunking boundaries.

3. **Dependency & Code Scanning**:
   - Automated Static Application Security Testing (SAST) is enforced via `bandit`.
   - Known Common Vulnerabilities and Exposures (CVEs) are monitored and blocked via `pip-audit`.
   - Automated dependency version and patch tracking is managed via GitHub Dependabot.

4. **Zero Cloud Leaks**:
   - The application does not communicate with external cloud LLMs (OpenAI, Anthropic, Google Cloud).
   - All weights, embeddings, vector stores, and relational records reside within local Docker volumes.

## Reporting a Vulnerability

If you discover a security vulnerability within this project:

1. **Do NOT open a public GitHub issue.**
2. Send an email to the repository maintainers or report via GitHub Private Vulnerability Reporting under the **Security** tab.
3. Please include:
   - A detailed description of the vulnerability.
   - Reproduction steps or proof-of-concept (PoC) payload.
   - Potential impact assessment.
4. Maintainers will acknowledge receipt within 48 hours and provide a remediation timeline.
